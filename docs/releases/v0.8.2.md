# BountyBreak 0.8.2

BountyBreak 0.8.2 gives the independent bug bounty operations layer a clearer product identity and a faster first run for approved Daybreak Blue workflows.

## What changed

- Renamed ScopeRook to BountyBreak across the dashboard, documentation, MCP server, resources, prompts, and release package.
- Replaced the former red/green look with a midnight and electric-blue interface plus a small dawn accent.
- Added an original horizon-and-target product mark.
- Moved a centered three-step Quickstart to the top of the README and dashboard.
- Changed the primary MCP tool namespace to `bountybreak_*`.
- Retained `scoperook_*` tool calls, resource and prompt identifiers, and the former Python entry-point filenames as migration aliases through the 0.8 release line.

## Product boundary

BountyBreak stores durable scope, candidate, validation, evidence, outcome, time, cost, and cash records. It does not scan targets, hold credentials, run arbitrary commands, or submit reports. Users supply their own approved Daybreak Blue access and any separately authorized execution tools.

BountyBreak is independent and is not affiliated with or endorsed by OpenAI.
