# BountyBreak 0.8.4

BountyBreak 0.8.4 adds the local data lifecycle required for a durable private beta. Researchers can inspect a store, create a manifest-backed backup, verify it independently, restore it into a new directory, and migrate legacy engagement records only after a rollback archive succeeds.

## Data protection

- `doctor` reports legacy, corrupt, and unsupported future-schema records without changing them.
- `backup` stores valid engagement trees and the local tool registry with per-file SHA-256 values.
- `verify` checks the archive structure, manifest, sizes, hashes, and engagement schemas.
- `restore` verifies first, extracts through a staging directory, and refuses every existing destination.
- `migrate` writes a verified pre-migration archive before atomic record updates.
- Downgrade and rollback restore the exact pre-migration archive into a new path instead of attempting a lossy reverse migration.

The workflow is a local CLI and is deliberately absent from MCP. Backups are not encrypted and must be placed on storage protected by the researcher.

## Validation

The focused suite covers exact byte round trips, tampered payloads, traversal, symlinks, existing destinations, corrupt records, future schemas, and legacy rollback. The complete repository suite, compile checks, stdio handshake, clean archive scan, and extracted-archive test remain required before publication.

## Release boundary

BountyBreak 0.8.4 remains a supervised private-beta candidate. It does not send target traffic, launch scanners, hold raw credentials, run arbitrary commands, provide Daybreak Blue access, or submit reports. Signed distribution and repeated outside-researcher use remain gates before an unattended paid public launch.
