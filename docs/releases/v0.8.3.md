# BountyBreak 0.8.3

BountyBreak 0.8.3 hardens the continuous workflow using a sanitized three-program field validation. The pass used existing authorized research records and sent no new target traffic.

## What changed

- Historical program reviews retain their source timestamps and optional program-specific freshness limits.
- Unmeasured time and cost stay unknown instead of becoming false zeroes.
- Closed and paused targets keep their recorded wait or stop condition; the Daybreak brief no longer invents a new hunting task for them.
- Engagement records use schema version 1, accept legacy unversioned records, and preserve unsupported future versions without queueing them.
- The repository now includes a privacy notice, threat model, real-program validation record, and SPDX 2.3 SBOM generator.

## Validation

- 53 deterministic tests pass, including the 100-target and 5,000-session portfolio trial.
- A fresh stdio process completed initialize, tool listing, and status calls with 40 tools and empty stderr.
- The three-program field store produced eighteen history events, zero hunt-ready targets, and no next target.
- Compilation, whitespace checks, and the private-store credential-pattern scan passed.

## Product boundary

BountyBreak 0.8.3 is a supervised private-beta candidate. It does not send target traffic, launch scanners, hold raw credentials, run arbitrary commands, provide Daybreak Blue access, or submit reports. Signed distribution, backup and restore, and repeated outside-researcher use remain gates before an unattended paid public launch.
